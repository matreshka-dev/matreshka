Matreshka — инструкции для агентов

Структура

- client/ — Angular-клиент.
- bff/ — BFF runtime и DSL компонентов.
- gateway/ — транспортный шлюз.
- protocols/client-bff-protocol/ — wire-контракт client ↔ BFF (@matreshka/client-bff-protocol).
- protocols/gateway-bff-protocol/ — wire-контракт gateway ↔ BFF (@matreshka/gateway-bff-protocol).
- shared/ — утилиты рантайма для BFF и клиента.
- docs/ — документация проекта.
- .cursor/skills/ — скиллы для агентов (platform-action — платформенные команды; component-action — imperative-команды BFF-компонентов на клиент).

Работа с изменениями

- Не изменяй файлы за пределами текущей задачи.
- Не редактируй сгенерированные файлы вручную.
- Не публикуй пакеты и не создавай релизы без прямого запроса.
- При изменении публичного API обновляй связанную документацию.

Форматирование

После изменения исходного кода запускай npm run format --silent -- --log-level=error в каждом затронутом пакете:

- client/
- bff/
- gateway/
- protocols/client-bff-protocol/
- protocols/gateway-bff-protocol/
- shared/

Для правок только Markdown и конфигурации запускать форматирование не нужно.

Проверка

- Запускай только проверки, релевантные текущим изменениям.
- Для client, gateway, обоих protocol-пакетов и shared запускай npm run lint --silent.
- Для bff запускай npx eslint ..
- Для проверки типов запускай соответствующую проекту команду TypeScript, если она предусмотрена.
- Для проверки общей сборки пакетов используй npm run build --silent из корня репозитория.
- Запускай релевантные тесты после изменения логики.
- Не запускай повторно успешно выполненные проверки без необходимости.
- Не исправляй посторонние ошибки, не связанные с текущей задачей.

Вывод команд

- Минимизируй вывод команд, чтобы не расходовать контекст на несущественную информацию.
- При успешном выполнении проверки достаточно краткого подтверждения результата.
- Не выводи списки обработанных файлов и служебную информацию, если они не нужны для диагностики.
- Сохраняй ошибки и предупреждения, необходимые для исправления проблем.
- Не подавляй диагностический вывод при неудачном выполнении команд.
- Не запускай повторно успешно выполненные проверки без необходимости.
- Не используй дополнительные скрипты и обёртки для подавления вывода, если задача решается штатными параметрами команд.

Примечание: --log-level=error применим, если в пакетах используется Prettier 3.x. Если у отдельных пакетов другая версия, стоит проверить поддержку этого параметра. --silent у npm сам по себе не скрывает вывод дочерних процессов.
