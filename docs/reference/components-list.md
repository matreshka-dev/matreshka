# Компоненты: Полный Список

> Справочник. Не читайте подряд — начните с [components-basics.md](../guides/components-basics.md) и [getting started](../getting-started/overview.md).

Этот файл — полный каталог публичных компонентов matreshka из `bff/components`.

Если нужен не полный справочник, а обзорная логика и общие абстракции, сначала стоит прочитать [components-basics.md](../guides/components-basics.md).

## Как читать этот список

Ниже компоненты сгруппированы по ролям:

- `entry`
- layout
- aliases
- inputs
- outputs
- charts
- special

Для каждого компонента указаны:

- назначение;
- свойства;
- тип каждого свойства;
- практический смысл свойства;
- события и методы, если они есть;
- маленький пример.

## Общие соглашения

### Общие свойства обычных компонентов

Большинство обычных компонентов наследуют базовые свойства `Component`.

| Свойство         | Тип                                  | Назначение                                                             |
| ---------------- | ------------------------------------ | ---------------------------------------------------------------------- |
| `colors`         | `Partial<Record<ColorRole, string>>` | Цветовые роли компонента после сериализации.                           |
| `font`           | `FontStackToken`                     | Шрифтовой стек компонента.                                             |
| `scale`          | `number`                             | Масштаб компонента целиком, включая зависимые размеры и отступы.       |
| `textAlign`      | `TextAlign`                          | Горизонтальное выравнивание текста.                                    |
| `textDecoration` | `TextDecoration`                     | Оформление текста: `none`, `underline`, `line-through` (зачёркивание). |
| `gridItem`       | `GridItem`                           | Настройки размещения компонента внутри `grid`.                         |
| `link`           | `{ value: string }`                  | Делает компонент ссылкой с переходом по URL.                           |

### Общие поля init-конфига

При создании компонента часто доступны общие поля из `ComponentInitConfig`.

| Поле           | Тип                                                                                | Назначение                                 |
| -------------- | ---------------------------------------------------------------------------------- | ------------------------------------------ |
| `colors`       | `Partial<Record<ColorRole, ColorToken>>`                                           | Цветовые токены до сериализации.           |
| `conditions`   | `Condition[] \| (() => Condition[])`                                               | Условия видимости компонента.              |
| `rules`        | `{ conditions: [Condition, ...Condition[]]; overrides: Partial<...> }[]`           | Условные переопределения свойств.          |
| `onShow`       | `ServerComponentAction<..., undefined> \| ServerComponentAction<..., undefined>[]` | Обработчик показа компонента.              |
| `onHide`       | `ServerComponentAction<..., undefined> \| ServerComponentAction<..., undefined>[]` | Обработчик скрытия компонента.             |
| `onMouseEnter` | `ServerComponentAction<..., undefined> \| ServerComponentAction<..., undefined>[]` | Обработчик наведения курсора на компонент. |
| `onMouseLeave` | `ServerComponentAction<..., undefined> \| ServerComponentAction<..., undefined>[]` | Обработчик ухода курсора с компонента.     |

### Что такое `ServerComponentAction`

`ServerComponentAction<ComponentType, PayloadType>` — это действие, которое выполняется по событию компонента.

Практически это значит:

- можно повесить серверный обработчик;
- можно повесить `LocalAction`;
- тип `PayloadType` описывает, что придет в `payload`;
- у самого действия могут быть `conditions`, которые решают, запускать ли это действие после события.

Подробнее логика `conditions` у действий описана в `events-and-actions.md`.

### Что такое `MixedWithCallbacksArray<T>`

Во многих контейнерах `content` имеет тип:

```ts
(T | (() => T | T[] | undefined))[]
```

Это позволяет передавать:

- готовые компоненты;
- функции, которые возвращают компонент;
- функции, которые возвращают несколько компонентов;
- функции, которые могут вернуть `undefined`.

### Что такое `Overlay[]`

Во многих компонентах встречается свойство `overlays`. Это список компонентов, которые нужно показать поверх текущего компонента или экрана: например, floating button, badge, подсказку или другой небольшой слой.

Каждый overlay содержит сам компонент и якоря позиционирования. Подробно эта модель описана в `overlays.md`.

### Как понимать `flexItem` и `size`

У `stack`, `grid`, `image`, `map` и `board` поведение внутри родительского `stack` задаёт `flexItem` (`FlexItemSpec`):

- `{ grow: 1 }` — относительный вес рядом с соседями;
- `{ basis: 56 }` — размер; число `> 1` в `basis` — логические пиксели;
- `basis` может быть `{ value, unit }`, плюс явные `grow` / `shrink`.

Свойство `size` у других компонентов означает другое:

- `popover.size` — ширина поповера: `> 1` — пиксели, `0..1` — доля ширины якоря;
- `icon.size` и `line.size` — размер иконки и толщина линии.

Важно: на стороне BFF такие размеры обычно задаются в пикселях для удобства описания DSL и соответствия макетам, но на клиенте они конвертируются в `rem`. Это нужно, чтобы UI не был жестко привязан к CSS-пикселям, а масштабировался вместе с базовым размером шрифта, настройками доступности и общей typographic scale клиента.

### Как понимать `value | ref` у output-компонентов

Почти все output-компоненты работают по одному паттерну:

- либо вы передаете статическое `value`;
- либо передаете `ref` на значение в `Context`.

Обычно это не два одновременно используемых поля, а два альтернативных способа задать источник данных.

### Как понимать `ref` у input-компонентов

У input-компонентов `ref` обязателен, потому что они не хранят значение внутри себя, а редактируют поле в `Context`.

## Entry-компоненты

У `entry`-компонентов есть собственный lifecycle (`destroy()`, `destroy$`), они не поддерживают `conditions` и используют `onEnter` / `onLeave` вместо `onShow` / `onHide`.

Короткое правило:

- `onShow` / `onHide` описывают обычные узлы внутри уже существующего UI;
- `onEnter` / `onLeave` описывают самостоятельный entry-контейнер.

### `Page`

Зачем нужен:

- основной экран приложения;
- корневая точка входа для route;
- контейнер для содержимого страницы.

Сериализуемые свойства:

| Свойство     | Тип               | Назначение                           |
| ------------ | ----------------- | ------------------------------------ |
| `title`      | `string`          | Заголовок страницы.                  |
| `content`    | `Componentable[]` | Готовое дерево компонентов страницы. |
| `overlays`   | `Overlay[]`       | Оверлеи поверх страницы.             |
| `statusCode` | `StatusCode`      | HTTP-статус страницы.                |

Переопределяемые методы:

| Метод          | Возвращает                                     | Назначение                                             |
| -------------- | ---------------------------------------------- | ------------------------------------------------------ |
| `title()`      | `string`                                       | Формирует заголовок страницы.                          |
| `content()`    | `MixedWithCallbacksArray<StandaloneComponent>` | Возвращает содержимое страницы.                        |
| `overlays()`   | `Overlay[]`                                    | Возвращает page-level overlays.                        |
| `statusCode()` | `StatusCode`                                   | Возвращает статус страницы.                            |
| `boot()`       | `Promise<unknown>`                             | Выполняет подготовку перед отправкой страницы клиенту. |

Lifecycle-события:

| Метод        | Payload                  | Назначение                                                  |
| ------------ | ------------------------ | ----------------------------------------------------------- |
| `onScroll()` | `ComponentScrollPayload` | Реакция на прокрутку страницы.                              |
| `onEnter()`  | `undefined`              | Реакция на первый показ страницы как entry-компонента.      |
| `onLeave()`  | `undefined`              | Реакция на начало ухода страницы; lifecycle стартует сразу. |

Пример:

```ts
export class HomePage extends Page {
  protected title() {
    return "Главная";
  }

  protected content() {
    return [text("Привет")];
  }
}
```

Пример `statusCode()`:

```ts
import StatusCode from "@matreshka/bff/core/types/status-code";

class NotFoundPage extends Page {
  protected title() {
    return "Не найдено";
  }

  statusCode() {
    return StatusCode.NotFound;
  }

  protected content() {
    return [text("Страница не найдена")];
  }
}
```

`boot()` полезен, когда нужно подготовить состояние до сериализации страницы:

```ts
class ProfilePage extends Page {
  async boot() {
    await this.profileContext.init();
    return super.boot();
  }

  protected title() {
    return "Профиль";
  }

  protected content() {
    return [text(this.profileContext.ref("name"))];
  }
}
```

Пример `onEnter()`:

```ts
class FeedPage extends Page {
  protected onEnter() {
    return () => {
      console.log("Страница показана клиенту");
    };
  }

  protected title() {
    return "Лента";
  }

  protected content() {
    return [text("Контент ленты")];
  }
}
```

Пример `onScroll()` и другие обработчики событий подробнее описаны в `events-and-actions.md`.

### `dialog()` / `Dialog`

Зачем нужен:

- самостоятельный слой поверх страницы;
- подтверждение действия;
- отдельный сценарий ввода.

Свойства:

| Свойство   | Тип                                    | Назначение                                                 |
| ---------- | -------------------------------------- | ---------------------------------------------------------- |
| `content`  | `StandaloneComponent[]`                | Содержимое диалога.                                        |
| `anchors`  | `[OverlayAnchor, ...OverlayAnchor[]]?` | Позиционирование диалога на экране.                        |
| `modal`    | `boolean?`                             | `true` или `undefined` — модальный, `false` — немодальный. |
| `overlays` | `Overlay[]?`                           | Оверлеи внутри диалога.                                    |
| `backdrop` | `{ onEnter?, onLeave? }?`              | Анимации подложки модального диалога (`::backdrop`).       |
| `onEnter`  | `ServerComponentAction<...>[]?`        | Реакция на первый показ диалога.                           |
| `onLeave`  | `ServerComponentAction<...>[]?`        | Реакция на начало закрытия; lifecycle стартует сразу.      |

Особенность init:

- `content` можно передавать как `MixedWithCallbacksArray<StandaloneComponent>`.
- `backdrop.onEnter` / `backdrop.onLeave` — локальные анимации подложки; см. `cookbook.md`.

Методы:

| Метод     | Назначение                                 |
| --------- | ------------------------------------------ |
| `close()` | Отправляет клиенту команду закрыть диалог. |

Пример:

```ts
dialog(
  {
    modal: true,
    onEnter: () => console.log("Диалог открыт"),
    onLeave: () => console.log("Диалог закрывается"),
  },
  [text("Подтвердите действие")],
);
```

### `popover()` / `Popover`

Зачем нужен:

- локальный всплывающий UI рядом с якорем;
- меню действий;
- contextual UI рядом с конкретным компонентом.

Свойства:

| Свойство       | Тип                             | Назначение                                                   |
| -------------- | ------------------------------- | ------------------------------------------------------------ |
| `content`      | `StandaloneComponent[]`         | Содержимое popover.                                          |
| `positionArea` | `PopoverPositionArea?`          | Область позиционирования относительно якоря.                 |
| `size`         | `number?`                       | Ширина popover: `> 1` — пиксели, `0..1` — доля ширины якоря. |
| `overlays`     | `Overlay[]?`                    | Оверлеи внутри popover.                                      |
| `onEnter`      | `ServerComponentAction<...>[]?` | Реакция на первый показ popover.                             |
| `onLeave`      | `ServerComponentAction<...>[]?` | Реакция на начало закрытия; lifecycle стартует сразу.        |

Методы:

| Метод     | Назначение                    |
| --------- | ----------------------------- |
| `close()` | Закрывает popover на клиенте. |

Пример:

```ts
popover(
  {
    positionArea: PopoverPositionArea.Bottom,
  },
  [text("Меню")],
);
```

## Layout-компоненты

### `stack()` / `Stack`

Зачем нужен:

- основной layout-компонент matreshka;
- аналог flex-контейнера;
- строка или колонка с управляемыми gap, align, padding и scroll.

Свойства:

| Свойство           | Тип                                                           | Назначение                                                                             |
| ------------------ | ------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `content`          | `StandaloneComponent[]`                                       | Дочерние компоненты контейнера.                                                        |
| `direction`        | `StackDirection?`                                             | Направление layout: горизонтальное или вертикальное.                                   |
| `align`            | `{ main?: StackMainAxisAlign; cross?: StackCrossAxisAlign }?` | Выравнивание по главной и поперечной оси.                                              |
| `gap`              | `number?`                                                     | Расстояние между дочерними компонентами.                                               |
| `overflow`         | `Overflow?`                                                   | CSS `overflow`. Без значения клиент использует `auto`.                                 |
| `wrap`             | `FlexWrap?`                                                   | CSS `flex-wrap`: `nowrap`, `wrap`, `wrap-reverse`, `balance` и комбинации с `balance`. |
| `flexItem`         | `FlexItemSpec?`                                               | Поведение внутри родительского `stack`.                                                |
| `radius`           | `RadiusPx?`                                                   | Скругление углов контейнера.                                                           |
| `padding`          | `PaddingPx?`                                                  | Внутренние отступы.                                                                    |
| `safeArea`         | `SafeAreaSide[]?`                                             | Стороны, на которых к padding добавляется safe area.                                   |
| `overlays`         | `Overlay[]?`                                                  | Оверлеи поверх контейнера.                                                             |
| `surface`          | `boolean?`                                                    | Включает фон поверхности.                                                              |
| `outline`          | `ComponentOutline[]?`                                         | Рамка, тень или другой outline-эффект.                                                 |
| `focusWithinStyle` | `boolean?`                                                    | Применяет focus-стиль, если фокус внутри потомков.                                     |
| `disabled`         | `boolean?`                                                    | Делает контейнер неинтерактивным.                                                      |

События:

| Поле init   | Payload                  | Назначение                       |
| ----------- | ------------------------ | -------------------------------- |
| `onClick`   | `unknown`                | Реакция на клик по контейнеру.   |
| `onKeyDown` | `{ key: string }`        | Реакция на нажатие клавиши.      |
| `onScroll`  | `ComponentScrollPayload` | Реакция на прокрутку контейнера. |

Методы:

| Метод                                       | Назначение                         |
| ------------------------------------------- | ---------------------------------- |
| `scrollTo(value: number \| ScrollToPosition, smooth?: boolean)` | Программно прокручивает контейнер. |

`scrollTo` передаёт на клиент команду `component-scroll-to`. Для типовых целей используйте enum **`ScrollToPosition`** (из `@matreshka/bff/components`):

| Значение | Эффект |
| -------- | ------ |
| `ScrollToPosition.Start` (`0`) | Начало оси (`scrollTop` / `scrollLeft` = 0). |
| `ScrollToPosition.End` | Конец оси (зарезервированное значение протокола, не пишите число вручную). |
| отрицательное число, кроме `End` | Отступ от конца: `maxScroll + value` (например `-16` — 16 логических px до низа). |

```ts
import { ScrollToPosition } from "@matreshka/bff/components";

messageList.scrollTo(ScrollToPosition.End); // вниз после нового сообщения
messageList.scrollTo(-24); // отступ 24 px от низа
messageList.scrollTo(ScrollToPosition.Start, true); // плавно к началу
```

Пример:

```ts
stack(
  {
    direction: StackDirection.Horizontal,
    gap: 12,
    padding: { top: 16, bottom: 16 },
    safeArea: [SafeAreaSide.Top, SafeAreaSide.Bottom],
  },
  [text("Первый"), text("Второй")],
);
```

`safeArea` задаётся явно и поддерживает `Top`, `Bottom`, `Start` и `End`.
Значение системного отступа определяется клиентской платформой и прибавляется
к соответствующему значению `padding`. Если `padding` для стороны не задан,
safe area прибавляется к нулю. `Start` и `End` автоматически учитывают LTR/RTL.

Пиксельный `flexItem.basis` (`> 1`) включает padding, а safe area ещё увеличивает этот
отступ — контент сжимается. Это не проявляется при `{ grow }`. Не ставьте
`safeArea` на контейнер с пиксельным `basis`: вынесите inset на обёртку
(`column`, `row`, `surface`) без `flexItem` и без `padding`. Подробнее — в
[`layout.md`](../guides/layout.md), раздел «`flexItem`, `padding` и `safeArea`».

Настройка также доступна алиасам `row`, `column`, `surface` и `button`, поскольку
они наследуют конфигурацию `stack`. Каждый контейнер с указанным `safeArea`
применяет отступ независимо; автоматического исключения вложенных контейнеров нет.

### `grid()` / `Grid`

Зачем нужен:

- двумерная сетка;
- layout со строгими колонками;
- табличные и карточные сценарии.

Свойства:

| Свойство   | Тип                                               | Назначение                                                   |
| ---------- | ------------------------------------------------- | ------------------------------------------------------------ |
| `content`  | `ComponentSequence<unknown, StandaloneComponent>` | Ячейки сетки. Может включать обычные компоненты и `forEach`. |
| `columns`  | `GridTemplateColumnsValue`                        | Описание колонок grid.                                       |
| `gap`      | `GridGap?`                                        | Отступы между строками и колонками.                          |
| `flexItem` | `FlexItemSpec?`                                   | Поведение внутри родительского `stack`.                      |
| `surface`  | `boolean?`                                        | Включает фон поверхности у grid.                             |

Как понимать `columns`:

```ts
GridTemplateColumns.Subgrid
| number
| { min: number; max: number }
| (GridColumnSize | number | { min: number; max: number })[]
```

Это позволяет:

- задать одинаковое число колонок;
- смешивать fixed/flexible колонки;
- описывать диапазон `min/max`;
- использовать `subgrid`.

Дополнительно у дочерних элементов часто используется:

| Свойство   | Тип        | Назначение                                             |
| ---------- | ---------- | ------------------------------------------------------ |
| `gridItem` | `GridItem` | Настраивает позицию и растяжение элемента внутри grid. |

Пример:

```ts
grid(
  {
    columns: [1, 1],
    gap: 12,
  },
  [button([text("Отмена")]), button([text("Сохранить")])],
);
```

### `line()` / `Line`

Зачем нужен:

- разделитель между блоками;
- горизонтальная или вертикальная линия.

Свойства:

| Свойство | Тип       | Назначение        |
| -------- | --------- | ----------------- |
| `size`   | `number?` | Толщина линии.    |
| `radius` | `number?` | Скругление линии. |

Пример:

```ts
line({ size: 1 });
```

### `container()` / `Container`

Зачем нужен:

- обернуть группу компонентов без собственной layout-модели;
- применить общие `conditions`, `colors` и другие базовые свойства к группе детей.

Свойства:

| Свойство  | Тип                     | Назначение                      |
| --------- | ----------------------- | ------------------------------- |
| `content` | `StandaloneComponent[]` | Дочерние компоненты контейнера. |

Особенность init:

- `content` можно передавать как `MixedWithCallbacksArray<ContentType>`.

Пример:

```ts
container([text("Заголовок"), text("Описание")]);
```

## Aliases над `stack`

### `button()` / `Button`

Зачем нужен:

- интерактивный контейнер-кнопка;
- готовый паттерн поверх `stack`.

Наследует почти все свойства `stack`, но автоматически задает:

- `direction: horizontal`;
- `surface: true`;
- `overflow: Overflow.Hidden`;
- центрирование контента по обеим осям.

Свойства:

| Свойство  | Тип                                                                   | Назначение                                                   |
| --------- | --------------------------------------------------------------------- | ------------------------------------------------------------ |
| `content` | `StandaloneComponent \| MixedWithCallbacksArray<StandaloneComponent>` | Содержимое кнопки. Можно передать один компонент или массив. |

Также поддерживает остальные свойства и события `stack`, кроме тех, которые alias фиксирует сам.

Пример:

```ts
button({ onClick: submitForm }, [text("Отправить")]);
```

### `row()` / `Row`

Зачем нужен:

- короткая форма горизонтального `stack`.

Особенность:

- это `stack`, у которого `direction` всегда равен `StackDirection.Horizontal`.

Пример:

```ts
row([icon({ size: 24 }, "home"), text("Главная")]);
```

### `column()` / `Column`

Зачем нужен:

- короткая форма вертикального `stack`.

Особенность:

- это `stack`, у которого `direction` всегда равен `StackDirection.Vertical`.

Пример:

```ts
column([text("Заголовок"), text("Описание")]);
```

### `surface()` / `Surface`

Зачем нужен:

- готовый контейнер с включенной поверхностью;
- карточки, панели, секции.

Особенность:

- это `stack`, у которого `surface` всегда равно `true`.

Пример:

```ts
surface(
  {
    padding: 16,
  },
  [text("Карточка")],
);
```

## Input-компоненты

Общее для всех input-компонентов:

| Свойство | Тип      | Назначение                                              |
| -------- | -------- | ------------------------------------------------------- |
| `ref`    | `string` | Путь к полю в `Context`, которое редактирует компонент. |

На этапе init сюда передаётся типизированный `ContextRef<...>`, а после сериализации клиент получает строковый путь.

### `textInput()` / `TextInput`

Зачем нужен:

- однострочный текстовый ввод.

Свойства:

| Свойство      | Тип                       | Назначение                                                                             |
| ------------- | ------------------------- | -------------------------------------------------------------------------------------- |
| `ref`         | `ContextRef<string, ...>` | Ссылка на строковое поле в `Context`.                                                  |
| `placeholder` | `string?`                 | Подсказка в пустом поле.                                                               |
| `kind`        | `TextInputKind?`          | Семантический вид поля; клиент сам выставляет подходящие `autocomplete` и `inputmode`. |
| `mask`        | `InputMaskProperties?`    | Маска ввода для форматируемых строк.                                                   |

`TextInputKind`:

| Значение                    | Что делает на клиенте                                            |
| --------------------------- | ---------------------------------------------------------------- |
| `TextInputKind.Text`        | Обычное текстовое поле без дополнительных атрибутов.             |
| `TextInputKind.Email`       | Включает `autocomplete="email"` и `inputmode="email"`.           |
| `TextInputKind.Tel`         | Включает `autocomplete="tel"` и `inputmode="tel"`.               |
| `TextInputKind.Url`         | Включает `autocomplete="url"` и `inputmode="url"`.               |
| `TextInputKind.Search`      | Включает `inputmode="search"`.                                   |
| `TextInputKind.OneTimeCode` | Включает `autocomplete="one-time-code"` и `inputmode="numeric"`. |

Если для выбранного `kind` атрибут не нужен, клиент просто не выставляет его.
Для подсказок менеджера паролей задавайте `kind`: клиент сам выставит `autocomplete` / `inputmode`.

`InputMaskProperties`:

| Поле          | Тип       | Назначение                                                                                                                                                                                                                                                                                             |
| ------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `value`       | `string`  | Шаблон маски целиком. В нем смешаны постоянные символы и позиции для пользовательского ввода. Например, в маске `"+7 (999) 999-99-99"` символы `+7 () -` фиксированы, а `9` обозначает места, куда пользователь вводит цифры.                                                                          |
| `dataSymbols` | `string`  | Набор символов из `value`, которые считаются "заполнителями" для пользовательского ввода. Например, если `dataSymbols: "9"`, то каждый символ `9` в `value` означает "сюда пользователь вводит один символ". Если указать `dataSymbols: "9A"`, то и `9`, и `A` будут восприниматься как позиции ввода. |
| `accept`      | `string?` | Ограничение на допустимые вводимые символы. Обычно это строка с регулярным выражением для одного символа или группы символов. Например, `"[0-9]"` означает, что в позиции маски можно вводить только цифры, а `"[A-Z]"` — только латинские заглавные буквы.                                            |
| `size`        | `number?` | Максимальное число пользовательских символов, которые можно ввести в позиции маски. Обычно это количество всех placeholder-символов в шаблоне. Например, для `"9999 9999"` логичный `size` — `8`, потому что пользователь вводит восемь цифр, а пробел в это число не входит.                          |

Как это работает вместе:

- `value` задает внешний вид строки;
- `dataSymbols` говорит, какие символы внутри `value` нужно заменить пользовательским вводом;
- `accept` ограничивает, что именно можно вводить в эти позиции;
- `size` ограничивает общее количество вводимых символов.

Пример маски телефона:

```ts
textInput(
  {
    placeholder: "Телефон",
    mask: {
      value: "+7 (999) 999-99-99",
      dataSymbols: "9",
      accept: "[0-9]",
      size: 10,
    },
  },
  this.context.ref("phone"),
);
```

Что здесь происходит:

- `+7 (` , `)` и `-` появляются автоматически;
- пользователь вводит только цифры;
- каждая `9` в шаблоне означает одну цифру;
- всего пользователь может ввести 10 цифр.

Пример маски кода:

```ts
textInput(
  {
    placeholder: "Код",
    mask: {
      value: "AA-9999",
      dataSymbols: "A9",
      accept: "[A-Z0-9]",
      size: 6,
    },
  },
  this.context.ref("promoCode"),
);
```

Что здесь происходит:

- шаблон имеет вид `AA-9999`;
- дефис вставляется автоматически;
- первые две позиции занимают символы `A`, последние четыре — `9`;
- все шесть пользовательских символов проходят через `accept`.

Пример:

```ts
import { TextInputKind, textInput } from "@matreshka/bff/components";

textInput(
  {
    placeholder: "Ваше имя",
  },
  this.context.ref("name"),
);

textInput(
  {
    kind: TextInputKind.Email,
    placeholder: "Email",
  },
  this.context.ref("email"),
);

textInput(
  {
    kind: TextInputKind.OneTimeCode,
    placeholder: "Код подтверждения",
  },
  this.context.ref("otp"),
);
```

### `numberInput()` / `NumberInput`

Зачем нужен:

- ввод числа.

Свойства:

| Свойство      | Тип                       | Назначение                                                                                                                                                                                                                                                      |
| ------------- | ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ref`         | `ContextRef<number, ...>` | Ссылка на числовое поле в `Context`.                                                                                                                                                                                                                            |
| `placeholder` | `string?`                 | Подсказка в пустом поле.                                                                                                                                                                                                                                        |
| `min`         | `number?`                 | Нижняя граница, которая пробрасывается в нативный HTML-атрибут `min` у `<input type="number">`. Клиент сам не реализует отдельную логику ограничения через кнопки; дальше поведение зависит от браузера и его встроенной валидации/интерпретации numeric input. |
| `max`         | `number?`                 | Верхняя граница, которая пробрасывается в нативный HTML-атрибут `max`. Как и `min`, используется именно браузером, а не отдельным кастомным кодом matreshka-клиента.                                                                                            |
| `step`        | `number?`                 | Шаг для нативного numeric input, который пробрасывается в HTML-атрибут `step`. Он влияет на встроенное поведение браузера: например, на допустимые значения, реакцию на стрелки клавиатуры, колесо мыши или встроенные controls браузера, если они есть.        |

Практическое следствие:

- если нужно строгое серверное ограничение, на одни только `min` / `max` / `step` полагаться не стоит, проверку лучше дублировать в `Context`/`zod` или в серверной логике.

Когда именно браузер обычно применяет их:

- `min` и `max` участвуют в нативной валидации numeric input;
- `step` участвует при инкременте/декременте значения встроенными механизмами браузера;
- `step` также может влиять на то, считается ли значение "корректным" с точки зрения нативного constraint validation;
- в некоторых средах mobile/web это может влиять только на поведение клавиатуры и встроенной валидации, без видимых элементов управления.

Пример:

```ts
numberInput(
  {
    placeholder: "Возраст",
    min: 18,
    max: 120,
    step: 1,
  },
  this.context.ref("age"),
);
```

Что это означает на практике:

- пользователь видит обычное числовое поле;
- браузер знает, что ожидается диапазон от `18` до `120`;
- шаг изменения значения считается равным `1`;
- но собственных кнопок matreshka для увеличения/уменьшения значения компонент не рисует.

Пример:

```ts
numberInput(
  {
    min: 0,
    max: 100,
    step: 1,
  },
  this.context.ref("age"),
);
```

## Output-компоненты

### Компоненты с локалезависимым форматированием

Часть output-компонентов отображает значение не "как есть", а через клиентское форматирование, зависящее от языка и региональных настроек браузера пользователя.

Что это означает на практике:

- один и тот же `value` может отображаться по-разному у пользователей из разных стран;
- формат даты, времени, валюты, разделителей тысяч и десятичного разделителя зависит от клиентской среды;
- если локаль явно не передана в свойствах компонента, обычно используется локаль браузера пользователя.

В текущем публичном DSL к таким сценариям относятся прежде всего:

- `currency()` — форматирование денежной суммы;
- `datetime()` — форматирование даты и/или времени.

Важно: отдельных публичных компонентов `date()` и `time()` в текущем `bff/components` нет. Для сценариев "только дата" или "только время" используется `datetime()` с соответствующими `options`.

### `text()` / `Text`

Зачем нужен:

- вывод текста;
- вывод значения из `Context`;
- строка с подстановками через `ref().toString()`.

Свойства:

| Свойство     | Тип                                | Назначение                                                       |
| ------------ | ---------------------------------- | ---------------------------------------------------------------- |
| `value`      | `string`                           | Статический текст.                                               |
| `ref`        | `CompatibleOutputRef<string, ...>` | Ссылка на строковое значение в `Context`.                        |
| `maxLines`   | `number?`                          | Ограничивает число строк при рендере.                            |
| `processors` | `TextOutputProcessorConfig[]?`     | Opt-in обработчики текста, например переносы строк и автоссылки. |

Важно:

- используется либо `value`, либо `ref`;
- если нужен смешанный текст, часто используют шаблонную строку с `ref().toString()`;
- `maxLines` остаётся layout-свойством и не относится к processors;
- processors применяются только если они явно указаны, без них текст рендерится без дополнительного парсинга.

Полезные enum'ы и хелперы:

- `TextOutputAutolinkTarget` — цель для клика по автоссылке (`Blank`, `Self`);
- `TextOutputAutolinkScheme` — разрешённые схемы (`Http`, `Https`, `Mailto`, `Tel`);
- `ColorRole.Link` — отдельная цветовая роль для автоссылок внутри `text()`;
- `lineBreaks()` — превращает `\n` в переносы строк;
- `autolink()` — превращает разрешённые URL-подобные фрагменты в ссылки.

Пример:

```ts
import {
  autolink,
  lineBreaks,
  text,
  ColorRole,
  TextOutputAutolinkScheme,
  TextOutputAutolinkTarget,
} from "@matreshka/bff/components";

text(
  {
    colors: {
      [ColorRole.Link]: accentLinkColorToken,
    },
    maxLines: 3,
    processors: [
      lineBreaks(),
      autolink({
        target: TextOutputAutolinkTarget.Blank,
        schemes: [
          TextOutputAutolinkScheme.Https,
          TextOutputAutolinkScheme.Mailto,
        ],
      }),
    ],
  },
  `Привет, ${this.context.ref("name").toString()}\nhttps://example.com`,
);
```

### `number()` / `Number`

Зачем нужен:

- вывод числа;
- вывод numeric value без отдельного клиентского форматтера.

Важно:

- по описанию API компонент предназначен для вывода числа;
- но в текущей клиентской реализации он рендерится как обычное `{{ value() }}` без `Intl.NumberFormat`;
- поэтому сейчас его отображение не имеет собственного локалезависимого форматирования, в отличие от `currency()` и `datetime()`.

Свойства:

| Свойство | Тип                                | Назначение                               |
| -------- | ---------------------------------- | ---------------------------------------- |
| `value`  | `number`                           | Статическое число.                       |
| `ref`    | `CompatibleOutputRef<number, ...>` | Ссылка на числовое значение в `Context`. |

Пример:

```ts
number(this.context.ref("count"));
```

### `currency()` / `Currency`

Зачем нужен:

- вывод денежной суммы;
- локалезависимое форматирование валюты на клиенте.

Важно:

- Отображение зависит от языка и региональных настроек браузера пользователя;
- могут отличаться символ валюты, позиция символа валюты, разделители тысяч и десятичный разделитель.

Свойства:

| Свойство            | Тип                                | Назначение                                |
| ------------------- | ---------------------------------- | ----------------------------------------- |
| `value`             | `number`                           | Статическая сумма.                        |
| `ref`               | `CompatibleOutputRef<number, ...>` | Ссылка на сумму в `Context`.              |
| `currency`          | `string`                           | Код валюты, например `"RUB"` или `"USD"`. |
| `minIntegerDigits`  | `number?`                          | Минимум целых разрядов.                   |
| `minFractionDigits` | `number?`                          | Минимум дробных разрядов.                 |
| `maxFractionDigits` | `number?`                          | Максимум дробных разрядов.                |

Пример:

```ts
currency(
  {
    currency: "RUB",
  },
  this.context.ref("price"),
);
```

Практический смысл:

- у одного пользователя сумма может выглядеть как `1,234.56 $`;
- у другого как `1 234,56 $`;
- это нормальное поведение, потому что формат выбирает клиентская локаль.

### `datetime()` / `Datetime`

Зачем нужен:

- вывод даты и времени;
- форматирование по локали клиента.

Важно:

- клиент форматирует значение через `toLocaleString(...)`;
- перед форматированием клиент создает `Date` через `new Date(value)`;
- если `locales` не заданы, используется локаль браузера пользователя;
- один и тот же timestamp у разных пользователей может отображаться в разном формате.

Практически `datetime()` покрывает сразу несколько сценариев:

- дата и время вместе;
- только дата;
- только время.

Свойства:

| Свойство  | Тип                                | Назначение                           |
| --------- | ---------------------------------- | ------------------------------------ |
| `value`   | `string`                           | ISO-строка даты/времени.             |
| `ref`     | `CompatibleOutputRef<string, ...>` | Ссылка на ISO-строку в `Context`.    |
| `locales` | `string[]?`                        | Явно заданные локали форматирования. |
| `options` | `DateTimeOptions?`                 | Опции `Intl.DateTimeFormat`.         |

Какой формат значения ожидается:

- на практике safest-вариант для значения в `Context` — строка в формате ISO 8601;
- лучше передавать полную дату и время, например `2026-06-25T08:30:00Z` или `2026-06-25T11:30:00+03:00`;
- именно такой формат наиболее предсказуемо парсится клиентом, потому что на клиенте используется `new Date(value)`.

Почему важен часовой пояс:

- если в строке есть `Z` или смещение вроде `+03:00`, момент времени зафиксирован однозначно;
- если часовой пояс не указан, клиент может интерпретировать строку в своей локальной таймзоне;
- из-за этого один и тот же `value` у пользователей в разных часовых поясах может превратиться в разные фактические моменты времени при парсинге;
- это особенно опасно, если BFF ожидает, что строка уже описывает точный timestamp, а не "локальное время пользователя".

Плохой пример:

```ts
this.context.setValue("createdAt", "2026-06-25T11:30:00");
```

В такой строке нет информации о часовом поясе, поэтому клиент может трактовать ее как локальное время своего устройства.

Хорошие примеры:

```ts
this.context.setValue("createdAt", "2026-06-25T08:30:00Z");
```

```ts
this.context.setValue("createdAt", "2026-06-25T11:30:00+03:00");
```

Обе строки содержат часовой пояс, поэтому момент времени интерпретируется однозначно.

Когда использовать `locales` и `options`:

- если `locales` не указаны, используется локаль пользователя;
- если вас устраивает формат пользователя, `locales` можно не указывать;
- если нужен предсказуемый формат для конкретной локали, ее лучше передать явно;
- если нужна только дата или только время, это обычно настраивается через `options`;
- через `options` можно собрать как полный `datetime`, так и только date-only или time-only отображение.

Пример:

```ts
datetime(
  {
    options: {
      dateStyle: "long",
      timeStyle: "short",
    },
  },
  this.context.ref("createdAt"),
);
```

Пример "только дата":

```ts
datetime(
  {
    options: {
      dateStyle: "long",
    },
  },
  this.context.ref("createdAt"),
);
```

Пример "только время":

```ts
datetime(
  {
    options: {
      timeStyle: "short",
    },
  },
  this.context.ref("createdAt"),
);
```

### `icon()` / `Icon`

Зачем нужен:

- отображение иконки.

Чем `icon` отличается от `image`:

- `icon` подходит именно для иконографики, а не для произвольных картинок;
- На практике это означает, что `icon` красится в нужный цветовой токен компонента и хорошо подчиняется теме, состояниям и палитре;
- `image` так не работает: она показывает исходное изображение как есть, со своими цветами.

Свойства:

| Свойство | Тип                                | Назначение                                       |
| -------- | ---------------------------------- | ------------------------------------------------ |
| `value`  | `string`                           | Идентификатор или строковое значение иконки.     |
| `ref`    | `CompatibleOutputRef<string, ...>` | Ссылка на строковое значение иконки в `Context`. |
| `size`   | `number`                           | Размер иконки в логических пикселях.             |

Пример:

```ts
icon({ size: 24 }, "https://unpkg.com/ionicons@7.1.0/dist/svg/home.svg");
```

### `image()` / `Image`

Зачем нужен:

- отображение изображения по URL.

Чем `image` отличается от `icon`:

- `image` рендерится как обычный `<img>`;
- она показывает исходное содержимое файла и сохраняет его собственные цвета;
- цветовые токены компонента не перекрашивают картинку так, как это происходит у `icon`;
- поэтому `image` подходит для фотографий, иллюстраций, логотипов, баннеров и любых произвольных изображений, а `icon` — для одноцветной иконографики, которая должна подстраиваться под тему.

Свойства:

| Свойство   | Тип                                   | Назначение                              |
| ---------- | ------------------------------------- | --------------------------------------- |
| `value`    | `string`                              | Статический URL изображения.            |
| `ref`      | `CompatibleOutputRef<string, ...>`    | Ссылка на URL изображения в `Context`.  |
| `ratio`    | `{ value: number; mode: RatioMode }?` | Соотношение сторон и режим отображения. |
| `radius`   | `RadiusPx?`                           | Скругление углов.                       |
| `flexItem` | `FlexItemSpec?`                       | Поведение внутри родительского `stack`. |

Как работает `ratio`:

- `ratio.value` задает `aspect-ratio` контейнера изображения;
- `ratio.mode` задает, как сама картинка вписывается в эту область;
- то есть `ratio` нужен не для "изменения файла", а для управления тем, как изображение будет показано внутри выделенного блока.

Что означает `ratio.value`:

- это числовое соотношение ширины к высоте;
- например, `1` означает квадрат `1:1`;
- `16 / 9` означает широкий прямоугольник `16:9`;
- `4 / 3` означает более классическую фотографическую пропорцию `4:3`.

Примеры:

- `value: 1` — аватар, квадратная карточка, иконка-превью;
- `value: 16 / 9` — баннер, обложка видео, hero-image;
- `value: 4 / 3` — обычная фотография или карточка товара.

Какие бывают `RatioMode`:

| `mode`              | Клиентский режим      | Когда использовать                                                                      |
| ------------------- | --------------------- | --------------------------------------------------------------------------------------- |
| `RatioMode.Fit`     | `object-fit: contain` | Когда нужно показать изображение целиком без обрезки.                                   |
| `RatioMode.Fill`    | `object-fit: cover`   | Когда нужно заполнить всю область, даже если края будут обрезаны.                       |
| `RatioMode.Stretch` | `object-fit: fill`    | Когда изображение должно растянуться на весь контейнер, даже ценой искажения пропорций. |

> `ImageMode` — deprecated alias для `RatioMode`.

Практический смысл режимов:

- `fit` полезен для логотипов, схем, иллюстраций и изображений, которые нельзя обрезать;
- `fill` полезен для обложек, карточек, баннеров и превью, где важнее занять всю область;
- `stretch` нужен редко и обычно подходит только для специальных случаев, когда допустимо визуальное искажение.

Пример с `fit`:

```ts
image(
  {
    ratio: {
      value: 1,
      mode: RatioMode.Fit,
    },
    flexItem: { basis: 96 },
  },
  this.context.ref("logoUrl"),
);
```

Такой вариант показывает квадратную область `1:1` и старается уместить картинку целиком без обрезки.

Пример с `fill`:

```ts
image(
  {
    ratio: {
      value: 16 / 9,
      mode: RatioMode.Fill,
    },
  },
  this.context.ref("coverUrl"),
);
```

Такой вариант делает область `16:9` и заполняет ее полностью, при необходимости обрезая края.

Пример с `stretch`:

```ts
image(
  {
    ratio: {
      value: 4 / 3,
      mode: RatioMode.Stretch,
    },
  },
  this.context.ref("diagramUrl"),
);
```

Такой вариант растягивает изображение на весь контейнер `4:3`, даже если исходные пропорции файла другие.

События:

| Поле init | Payload   | Назначение                      |
| --------- | --------- | ------------------------------- |
| `onClick` | `unknown` | Реакция на клик по изображению. |

Пример:

```ts

  {
    flexItem: { basis: 48 },
    radius: 24,
  },
  this.context.ref("avatar"),
);
```

### `iframe()` / `Iframe`

Зачем нужен:

- встраивание внешнего контента через `<iframe>`: видеоплееры, embed-страницы, виджеты.

Свойства:

| Свойство | Тип                                | Назначение                                   |
| -------- | ---------------------------------- | -------------------------------------------- |
| `value`  | `string`                           | Статический URL для атрибута `src`.          |
| `ref`    | `CompatibleOutputRef<string, ...>` | Ссылка на URL в `Context`.                   |
| `allow`  | `IframeAllow[]?`                   | Разрешения для атрибута `allow` iframe.      |
| `ratio`  | `{ value: number }?`               | Соотношение сторон через CSS `aspect-ratio`. |

Как работает `ratio`:

- задаётся через `ratio.value` и управляет CSS `aspect-ratio`;
- iframe занимает `width: 100%` родителя, а высота вычисляется из `aspect-ratio`;
- например, `ratio: { value: 16 / 9 }` делает область `16:9`, `ratio: { value: 800 / 268 }` — кастомную пропорцию под конкретный embed.

Доступные значения `IframeAllow`:

| Значение                       | Смысл                                              |
| ------------------------------ | -------------------------------------------------- |
| `IframeAllow.Fullscreen`       | Разрешает полноэкранный режим.                     |
| `IframeAllow.Autoplay`         | Разрешает автозапуск медиа.                        |
| `IframeAllow.ClipboardWrite`   | Разрешает запись в буфер обмена из iframe.         |
| `IframeAllow.PictureInPicture` | Разрешает режим «картинка в картинке».             |
| `IframeAllow.EncryptedMedia`   | Разрешает воспроизведение защищённого медиа (DRM). |

На клиенте значения из `allow` собираются в строку вида `"autoplay; fullscreen; clipboard-write; picture-in-picture; encrypted-media"`.

Пример для видеоплеера:

```ts
import { iframe, IframeAllow } from "@matreshka/bff";

iframe(
  {
    allow: [IframeAllow.Autoplay, IframeAllow.Fullscreen],
    ratio: { value: 16 / 9 },
  },
  "https://vkvideo.ru/video_ext.php?oid=1025087646&id=456239017",
);
```

Пример с `ref`:

```ts
iframe(
  {
    allow: [
      IframeAllow.Autoplay,
      IframeAllow.Fullscreen,
      IframeAllow.ClipboardWrite,
    ],
    ratio: { value: 800 / 268 },
  },
  this.context.ref("camEmbedUrl"),
);
```

### `forEach()` / `ForEach`

Зачем нужен:

- динамический список по массиву в `Context`;
- серверно-контролируемая синхронизация списка.

Свойства:

| Свойство    | Тип                                                                       | Назначение                                    |
| ----------- | ------------------------------------------------------------------------- | --------------------------------------------- |
| `ref`       | `CompatibleForEachRef<RefType>`                                           | Ссылка на массив в контексте.                 |
| `track`     | `(data: Item) => string`                                                  | Возвращает стабильный ключ элемента.          |
| `generator` | `(props: ForEachGeneratorProperties) => ComponentType \| ComponentType[]` | Строит UI для одного элемента массива.        |
| `preload`   | `boolean?`                                                                | Предзагружает строки списка в initial config. |
| `divider`   | `StandaloneComponent \| StandaloneComponent[]?`                           | Разделитель между элементами списка.          |

Что получает `generator`:

| Поле        | Тип                        | Назначение                           |
| ----------- | -------------------------- | ------------------------------------ |
| `component` | `Componentable`            | Текущий внутренний компонент списка. |
| `ref`       | `ForEachItemLink<RefType>` | Ссылка на текущий элемент массива.   |

Как работает `preload`:

- при `preload: true` BFF вызывает `generator(...)` для текущих элементов массива еще во время сериализации `forEach`;
- сгенерированные строки попадают прямо в initial config страницы;
- клиент может отрисовать список сразу, без ожидания первого отдельного sync-сообщения;
- после `onShow` компонент все равно подписывается на изменения контекста и продолжает обычную синхронизацию списка.

Что происходит без `preload`:

- initial config содержит сам контейнер `forEach`, но без заранее сериализованных строк;
- после `onShow` BFF делает первую синхронизацию списка отдельным `ForEachSyncComponentsMessage`;
- поэтому элементы появляются чуть позже, чем сам контейнер списка.

Зачем это нужно:

- чтобы уменьшить задержку первого отображения списка;
- чтобы список был виден сразу вместе со страницей;
- чтобы избежать краткой фазы "контейнер уже есть, а строки еще не пришли".

Плюсы `preload`:

- быстрее первый визуальный рендер списка;
- меньше ощущение догрузки для пользователя;
- особенно полезно для стартовых экранов и небольших списков.

Минусы `preload`:

- initial page payload становится больше;
- первая сериализация страницы становится тяжелее;
- данные могут измениться между сериализацией страницы и `onShow`, тогда BFF все равно пришлет дополнительную синхронизацию.

Когда `preload` обычно полезен:

- короткие списки;
- статичные или редко меняющиеся данные;
- важный контент, который должен быть виден сразу.

Когда `preload` лучше не включать:

- большие списки;
- часто меняющиеся данные;
- сценарии, где важнее уменьшить initial payload, чем мгновенно показать все строки.

Пример с `preload`:

```ts
forEach({
  ref: this.context.ref("items"),
  preload: true,
  track: (item) => item.id,
  generator: ({ ref }) => [text(ref.ref("title")), text(ref.ref("subtitle"))],
});
```

Что это дает:

- если `items` уже есть в контексте на момент построения страницы, строки отправятся сразу;
- пользователь увидит список вместе с остальным содержимым страницы;
- последующие изменения массива все равно будут синхронизироваться отдельными сообщениями.

Пример:

```ts
forEach({
  ref: this.context.ref("items"),
  track: (item) => item.id,
  generator: ({ ref }) => text(ref.ref("title")),
});
```

| `apiKey`   | `string`                                                     | Ключ API карт.                              |
| `center`   | `{ latitude: number; longitude: number; altitude?: number }` | Начальный центр карты.                      |
| `zoom`     | `number`                                                     | Начальный масштаб карты. По умолчанию `17`. |
| `flexItem` | `FlexItemSpec?`                                              | Поведение внутри родительского `stack`.     |
| `overlays` | `Overlay[]?`                                                 | Оверлеи поверх карты.                       |
| `markers`  | `(MapMarker \| ItemList<MapMarker>)[]?`                      | Статические и/или динамические маркеры (на wire — flat `SerializedMapMarker[]`). |

`MapMarker`:

| Поле          | Тип                                                                               | Назначение                                             |
| ------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------ |
| `coordinates` | `{ latitude: number; longitude: number }`                                         | Координаты маркера.                                    |
| `width`       | `number`                                                                          | Ширина маркера.                                        |
| `component`   | `StandaloneComponent`                                                             | Компонент, который используется как визуальный маркер. |
| `anchor`      | `{ vertical?: MapMarkerVerticalAnchor; horizontal?: MapMarkerHorizontalAnchor }?` | Точка привязки компонента-маркера к координате.        |

События:

| Поле init        | Payload                                                      | Назначение                           |
| ---------------- | ------------------------------------------------------------ | ------------------------------------ |
| `onCenterChange` | `{ latitude: number; longitude: number; altitude?: number }` | Реакция на изменение центра карты.   |
| `onZoomChange`   | `number`                                                     | Реакция на изменение масштаба карты. |

Методы:

| Метод               | Назначение                       |
| ------------------- | -------------------------------- |
| `setCenter(center)` | Программно меняет центр карты.   |
| `setZoom(zoom)`     | Программно меняет масштаб карты. |
| `zoomIn(step?)`     | Увеличивает zoom.                |
| `zoomOut(step?)`    | Уменьшает zoom.                  |

Пример:

```ts
import { itemList } from "@matreshka/bff/components";

map({
  apiKey: "MAP_API_KEY",
  center: {
    latitude: 55.75,
    longitude: 37.62,
  },
  zoom: 12,
  markers: [
    {
      coordinates: { latitude: 55.75, longitude: 37.62 },
      width: 100,
      component: text("HQ"),
    },
    itemList({
      ref: context.ref("offices"),
      track: (office) => office.id,
      generator: ({ ref }) => ({
        coordinates: {
          latitude: ref.value().lat,
          longitude: ref.value().lng,
        },
        width: 80,
        component: text(ref.value().name),
      }),
    }),
  ],
});
```

Подробнее про `itemList`: `item-list.md`.

### `board()` / `Board`

Зачем нужен:

- плоскость с компонентами по произвольным координатам `x`/`y`;
- панорамирование и масштабирование вида мышью и жестами;
- сценарии вроде дерева подразделений, схемы офиса, свободной раскладки карточек.

Это не HTML `<canvas>` и не flex/grid. Карточки — обычные компоненты matreshka. `(0, 0)` плоскости — левый верх, ось `y` вниз. `center` — точка плоскости в середине видимой области.

Свойства:

| Свойство   | Тип                         | Назначение                                           |
| ---------- | --------------------------- | ---------------------------------------------------- |
| `center`   | `{ x: number; y: number }?` | Начальный центр вида. По умолчанию `{ x: 0, y: 0 }`. |
| `zoom`     | `number?`                   | Начальный масштаб вида. По умолчанию `1`.            |
| `minZoom`  | `number?`                   | Минимальный масштаб. По умолчанию `0.25`.            |
| `maxZoom`  | `number?`                   | Максимальный масштаб. По умолчанию `4`.              |
| `flexItem` | `FlexItemSpec?`             | Поведение внутри родительского `stack`.              |
| `overlays` | `Overlay[]?`                | Оверлеи поверх доски.                                |
| `items`    | `(BoardItem \| ItemList<BoardItem>)[]?` | Карточки на плоскости (на wire — flat `SerializedBoardItem[]`). |

`BoardItem`:

| Поле        | Тип                        | Назначение                                |
| ----------- | -------------------------- | ----------------------------------------- |
| `position`  | `{ x: number; y: number }` | Координаты карточки в логических px.      |
| `component` | `StandaloneComponent`      | Компонент, который рисуется в этой точке. |

События:

| Поле init        | Payload                    | Назначение                          |
| ---------------- | -------------------------- | ----------------------------------- |
| `onCenterChange` | `{ x: number; y: number }` | Реакция на изменение центра вида.   |
| `onZoomChange`   | `number`                   | Реакция на изменение масштаба вида. |

Методы:

| Метод               | Назначение                      |
| ------------------- | ------------------------------- |
| `setCenter(center)` | Программно меняет центр вида.   |
| `setZoom(zoom)`     | Программно меняет масштаб вида. |
| `zoomIn()`          | Увеличивает zoom.               |
| `zoomOut()`         | Уменьшает zoom.                 |

Пример:

```ts
import { itemList } from "@matreshka/bff/components";

board({
  center: { x: 200, y: 120 },
  zoom: 1,
  items: [
    {
      position: { x: 120, y: 40 },
      component: surface({}, [text("Отдел")]),
    },
    itemList({
      ref: context.ref("teams"),
      track: (team) => team.id,
      generator: ({ ref }) => ({
        position: { x: ref.value().x, y: ref.value().y },
        component: text(ref.value().name),
      }),
    }),
  ],
});
```

Подробнее про `itemList`: `item-list.md`.
