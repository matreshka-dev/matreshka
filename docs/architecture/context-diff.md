# Context Diff Protocol

## 1. Назначение

Context Diff Protocol — протокол передачи изменений состояния Context между BFF и Client.

Вместо передачи полного состояния Context передаются только изменения, необходимые для приведения текущего состояния получателя к новому состоянию отправителя.

Протокол использует структуру Partial Tree — частичное JSON-дерево, в котором каждый узел может содержать:

- Новое значение.
- Изменения дочерних узлов.
- Операции удаления.
- Операции перемещения элементов массива.
- Инструкцию полной замены значения.

Основные преимущества:

- Минимизация сетевого трафика.
- Поддержка произвольной вложенности объектов и массивов.
- Отсутствие необходимости передавать полные пути изменённых свойств.
- Возможность комбинировать разные операции в одном сообщении.
- Автоматическая оптимизация между частичным обновлением и полной заменой.

Протокол не зависит от транспортного механизма и может использоваться поверх WebSocket, SSE и других каналов передачи данных.

## 2. Общая структура

Изменения передаются в виде обычного JSON-объекта.

Каждый ключ соответствует свойству исходного объекта или индексу массива.

Например:

Исходное состояние:

```json
{
  "user": {
    "name": "Иван",
    "age": 25,
    "active": true
  },
  "settings": {
    "theme": "light"
  }
}
```

Сообщение:

```json
{
  "user": {
    "name": "Пётр"
  }
}
```

После применения сообщения состояние будет выглядеть так:

```json
{
  "user": {
    "name": "Пётр",
    "age": 25,
    "active": true
  },
  "settings": {
    "theme": "light"
  }
}
```

Изменяется только `user.name`. Остальные свойства сохраняются.

### 2.1. Интерпретация узлов

| Представление                                    | Значение                       |
| ------------------------------------------------ | ------------------------------ |
| Примитив (`string`, `number`, `boolean`, `null`) | Замена значения                |
| Непустой объект                                  | Частичное обновление свойств   |
| Непустой массив                                  | Частичное обновление элементов |
| `{}`                                             | Нет изменений                  |
| `[]`                                             | Нет изменений                  |
| `{"$set": value}`                                | Полная замена узла             |

Пустые объекты и массивы требуют отдельного рассмотрения: они могут быть как полноценными значениями данных, так и пустыми деревьями изменений.

Для передачи пустого объекта или массива используется `$set`.

Если ключа ещё нет, непустой объект без `$remove`, `$move` и `$insert` создаёт его и записывает перечисленные свойства. Вложенные объекты создаются так же. Пустой объект и массив так передать нельзя: `{}` и `[]` означают отсутствие изменений, а непустой массив обновляет уже существующий массив по позиции.

Пример. В контексте нет `id31@1`. Сообщение:

```json
{
  "id31@1": {
    "index": "30"
  }
}
```

Результат:

```json
{
  "id31@1": {
    "index": "30"
  }
}
```

`$set` вокруг такого объекта описывает то же состояние и занимает больше места. Генератор оставляет короткую форму.

## 3. Специальные операции

Протокол определяет четыре специальные операции:

| Операция  | Назначение                                     |
| --------- | ---------------------------------------------- |
| `$set`    | Полная замена текущего узла                    |
| `$remove` | Удаление свойств объекта или элементов массива |
| `$move`   | Перемещение элементов массива                  |
| `$insert` | Вставка последовательности элементов массива   |

Операции располагаются непосредственно в узле, над которым выполняются.

Например:

```json
{
  "user": {
    "$remove": ["email"],
    "name": "Пётр"
  }
}
```

Здесь одновременно выполняются две операции над `user`:

- Удаляется свойство `email`.
- Обновляется свойство `name`.

Такой подход позволяет представлять несколько изменений одного объекта без повторения полного пути к нему.

## 4. Полная замена значения — $set

`$set` заменяет значение текущего узла целиком.

Используется для:

- Полной замены объектов, когда частичное дерево длиннее.
- Полной замены массивов и передачи нового массива.
- Передачи пустых объектов и массивов.
- Оптимизации передачи больших изменений.

Новый непустой объект без структурных операций передаётся деревом свойств и не требует `$set`.

### 4.1. Замена объекта

Сообщение:

```json
{
  "user": {
    "$set": {
      "name": "Пётр",
      "age": 30
    }
  }
}
```

Результат:

```json
{
  "user": {
    "name": "Пётр",
    "age": 30
  }
}
```

Предыдущие свойства объекта, отсутствующие в `$set`, удаляются.

### 4.2. Замена массива

Сообщение:

```json
{
  "items": {
    "$set": ["A", "B", "C"]
  }
}
```

Массив заменяется полностью.

### 4.3. Пустые значения

Для передачи пустого объекта:

```json
{
  "settings": {
    "$set": {}
  }
}
```

Для передачи пустого массива:

```json
{
  "items": {
    "$set": []
  }
}
```

### 4.4. Особенности

`$set` является терминальной операцией для текущего узла.

Если узел содержит `$set`, другие операции и дочерние инструкции на этом же узле не допускаются.

Вложенные специальные операции внутри значения `$set` не интерпретируются: значение рассматривается как обычные данные.

## 5. Удаление — $remove

`$remove` удаляет дочерние элементы текущего узла.

Операция поддерживает два типа аргументов:

- Строковые ключи — для объектов.
- Числовые индексы — для массивов.

### 5.1. Удаление свойств объекта

Исходное состояние:

```json
{
  "user": {
    "name": "Иван",
    "age": 25,
    "email": "ivan@example.com"
  }
}
```

Сообщение:

```json
{
  "user": {
    "$remove": ["email"]
  }
}
```

Результат:

```json
{
  "user": {
    "name": "Иван",
    "age": 25
  }
}
```

### 5.2. Удаление элементов массива

Исходное состояние:

```json
{
  "items": ["A", "B", "C", "D"]
}
```

Сообщение:

```json
{
  "items": {
    "$remove": [1, 3]
  }
}
```

Результат:

```json
{
  "items": ["A", "C"]
}
```

Все индексы относятся к исходному состоянию массива до выполнения удалений.

Поэтому удаление нескольких элементов не должно приводить к смещению индексов последующих операций.

### 5.3. Совместное использование

Удаление может комбинироваться с частичным обновлением других свойств того же объекта.

```json
{
  "user": {
    "$remove": ["email", "phone"],
    "name": "Пётр",
    "age": 26
  }
}
```

## 6. Перемещение элементов — $move

`$move` используется для изменения порядка элементов массива без передачи их содержимого повторно.

Формат:

```ts
type MoveOperation = Array<[from: number, to: number]>;
```

Каждая пара означает перемещение элемента из позиции `from` в позицию `to`.

### 6.1. Пример

Исходное состояние:

```json
{
  "items": ["A", "B", "C", "D"]
}
```

Сообщение:

```json
{
  "items": {
    "$move": [[3, 0]]
  }
}
```

Результат:

```json
{
  "items": ["D", "A", "B", "C"]
}
```

Элемент перемещается, а не копируется.

### 6.2. Несколько перемещений

Операции выполняются последовательно.

```json
{
  "items": {
    "$move": [
      [3, 0],
      [2, 1]
    ]
  }
}
```

Индексы каждой следующей операции относятся к массиву после предыдущего перемещения.

### 6.3. Особенности

- `$move` применяется только к массивам.
- Индексы должны быть целыми неотрицательными числами.
- Индексы перемещения относятся к состоянию массива после выполнения `$remove`.
- Каждая операция перемещения выполняется последовательно.
- Перемещение не изменяет содержимое элемента.

## 7. Вставка элементов — $insert

`$insert` добавляет последовательность новых элементов в массив, не передавая соседние элементы повторно.

Формат:

```ts
type InsertOperation = Array<[index: number, elements: Json[]]>;
```

Каждая пара вставляет `elements` в позицию `index`. Одна вставка — список из одной пары.

### 7.1. Пример

Исходное состояние:

```json
{
  "items": ["A", "C"]
}
```

Сообщение:

```json
{
  "items": {
    "$insert": [[1, ["B1", "B2"]]]
  }
}
```

Результат:

```json
{
  "items": ["A", "B1", "B2", "C"]
}
```

Элементы последовательности — обычные JSON-значения. Вложенные `$set`, `$remove`, `$move` и `$insert` внутри них не интерпретируются.

### 7.2. Несколько вставок

Операции выполняются последовательно, от первой пары к последней.

```json
{
  "items": {
    "$insert": [
      [0, ["X"]],
      [2, ["Y", "Z"]]
    ]
  }
}
```

Для массива `["A", "C"]` результат — `["X", "A", "Y", "Z", "C"]`.

Индекс каждой следующей операции относится к массиву после предыдущей вставки.

### 7.3. Особенности

- `$insert` применяется только к массивам.
- Индекс — целое число от `0` до текущей длины включительно.
- Последовательность элементов непустая.
- Индекс относится к состоянию массива после `$remove`, `$move` и предыдущих `$insert`.
- Вставка в конец допустима и равносильна дописыванию элементов.

## 8. Частичное обновление массивов

Для изменения содержимого отдельных элементов массива используются их индексы.

Например:

Исходное состояние:

```json
{
  "items": [
    {
      "id": 1,
      "name": "A",
      "active": true
    },
    {
      "id": 2,
      "name": "B",
      "active": true
    }
  ]
}
```

Сообщение:

```json
{
  "items": {
    "1": {
      "name": "C"
    }
  }
}
```

Результат:

```json
{
  "items": [
    {
      "id": 1,
      "name": "A",
      "active": true
    },
    {
      "id": 2,
      "name": "C",
      "active": true
    }
  ]
}
```

Обновляется только `items[1].name`.

### 8.1. Сочетание со структурными операциями

Частичное обновление элементов может комбинироваться с `$remove`, `$move` и `$insert`.

Порядок обработки:

1. `$remove`.
2. `$move`.
3. `$insert`.
4. Индексированные изменения.

Индексы частичных обновлений всегда относятся к итоговому массиву после структурных операций.

## 9. Автоматическая оптимизация Diff

Генератор Context Diff самостоятельно выбирает способ представления изменений.

Для каждого изменённого узла рассматриваются возможные варианты:

- Частичное обновление.
- Частичное обновление с `$remove`.
- Частичное обновление с `$move` для массивов.
- Вставка последовательности через `$insert`.
- Полная замена через `$set`.

Выбирается вариант с минимальным размером сериализованного JSON.

### 9.1. Изменение всех свойств объекта

Изменение всех свойств не означает необходимость полной замены.

Предыдущее состояние:

```json
{
  "user": {
    "name": "Иван",
    "age": 25,
    "city": "Москва"
  }
}
```

Новое состояние:

```json
{
  "user": {
    "name": "Пётр",
    "age": 30,
    "city": "Казань"
  }
}
```

Генератор может выбрать:

```json
{
  "user": {
    "name": "Пётр",
    "age": 30,
    "city": "Казань"
  }
}
```

Это обычно компактнее `$set`, поскольку не требует передачи дополнительного ключа операции.

### 9.2. Удаление одного свойства

При удалении свойства генератор сравнивает `$remove` с полной заменой объекта.

```json
{
  "user": {
    "$remove": ["email"]
  }
}
```

или:

```json
{
  "user": {
    "$set": {
      "name": "Иван",
      "age": 25
    }
  }
}
```

Выбор зависит от фактического размера сообщения.

### 9.3. Смешанные изменения

Генератор может комбинировать операции на одном узле и использовать разные стратегии на вложенных узлах.

Например:

```json
{
  "user": {
    "$remove": ["email"],
    "name": "Пётр",
    "settings": {
      "$set": {
        "theme": "dark"
      }
    }
  }
}
```

Здесь:

- `user` обновляется частично.
- `user.email` удаляется.
- `user.name` заменяется.
- `user.settings` заменяется полностью.

### 9.4. Оптимизация массивов

При сравнении массивов генератор определяет:

- Удалённые элементы.
- Перемещённые элементы.
- Вставленные последовательности.
- Изменения содержимого существующих элементов.
- Необходимость полной замены массива.

Для сопоставления элементов могут использоваться стабильные идентификаторы, например `id`, либо другие критерии идентичности, заданные приложением.

Если частичное представление оказывается больше полной замены, используется `$set`.

**Важно:** выбор операции является внутренней ответственностью генератора. Разработчику, использующему Context, не требуется самостоятельно определять, когда применять `$remove`, `$move`, `$insert` или `$set`.

Дописывание короткого хвоста отдельными индексами может оказаться компактнее `$insert`. Генератор сравнивает оба представления и оставляет более короткое.

## 10. Порядок применения сообщения

Получатель должен применять Partial Tree в определённой последовательности.

### Фаза 1. Remove

Обрабатываются операции удаления:

- Удаляются свойства объектов.
- Удаляются элементы массивов по исходным индексам.

### Фаза 2. Move

Обрабатываются перемещения элементов массивов.

Индексы относятся к состоянию массива после удаления.

Несколько перемещений выполняются последовательно.

### Фаза 3. Insert

В массив вставляются последовательности `$insert`.

Индекс каждой операции относится к массиву после `$remove`, `$move` и предыдущих вставок.

### Фаза 4. Apply

Применяются обычные узлы Partial Tree:

- Замена примитивов.
- Добавление свойств.
- Частичное обновление объектов.
- Частичное обновление элементов массивов.

### Фаза 5. Set

Выполняются полные замены узлов через `$set`.

На практике `$set` является терминальной операцией узла: если он присутствует, другие инструкции этого узла не допускаются и не применяются.

## 11. Контракт данных и ограничения

Протокол предназначен для передачи JSON-совместимых значений.

Поддерживаются:

- `string`
- `number`
- `boolean`
- `null`
- Объекты
- Массивы

Не используются:

- `undefined` как значение операции.
- Функции.
- Ссылки на экземпляры классов.
- Циклические ссылки.
- Специальные JavaScript-объекты без предварительной сериализации.

### 11.1. Зарезервированные ключи

Следующие ключи зарезервированы протоколом:

```ts
type ReservedKeys = "$set" | "$remove" | "$move" | "$insert";
```

Они не должны интерпретироваться как обычные пользовательские свойства в позиции, зарезервированной для операций.

Если пользовательским данным необходимо поддерживать такие ключи, транспортный формат должен предусматривать механизм экранирования.

### 11.2. Ошибки валидации

Получатель должен отклонять некорректные сообщения, в частности:

- `$remove` с неподходящим типом аргументов.
- `$move` для объекта.
- `$insert` для объекта, с пустой последовательностью или с индексом вне диапазона.
- Некорректные индексы массива.
- `$set` вместе с другими инструкциями того же узла.
- Неизвестные специальные операции.
- Некорректные JSON-значения.

Применение некорректного Diff не должно приводить к частичному повреждению состояния Context.

## 12. Использование в Matreshka

Context Diff Protocol является внутренним механизмом синхронизации состояния.

Типичный процесс:

1. В BFF изменяется состояние Context.
2. Генератор сравнивает предыдущее и новое состояния.
3. Формируется Partial Tree.
4. Partial Tree сериализуется в JSON.
5. Сообщение передаётся Client.
6. Client применяет изменения к локальному состоянию Context.

Упрощённая схема:

```text
BFF Context
    |
    v
Previous State + Next State
    |
    v
Diff Generator
    |
    v
Partial Tree
    |
    v
Transport
    |
    v
Client
    |
    v
Diff Applier
    |
    v
Updated Context
```

Протокол не определяет:

- Жизненный цикл Context.
- Механизм подписок.
- Правила доступа к свойствам.
- Транспортный формат внешнего сообщения.
- Механизм разрешения конфликтов между версиями состояния.

Эти задачи решаются соответствующими компонентами Matreshka.

## 13. Гарантии корректности

Основной инвариант протокола:

Применение Diff, сформированного между двумя состояниями, должно приводить к точному восстановлению целевого состояния.

```ts
const diff = createDiff(previous, next);

const result = applyDiff(previous, diff);

expect(result).toEqual(next);
```

Корректность должна сохраняться после сериализации и десериализации:

```ts
const serialized = JSON.stringify(diff);
const restored = JSON.parse(serialized);

const result = applyDiff(previous, restored);

expect(result).toEqual(next);
```

Таким образом, результат не должен зависеть от передачи JavaScript-объектов по ссылке или других особенностей среды выполнения.

## 14. Принципы развития протокола

При расширении Context Diff Protocol необходимо сохранять следующие принципы:

1. **Единый формат** — все изменения представляются через Partial Tree.
2. **Минимальный объём данных** — выбирается наиболее компактное корректное представление.
3. **Локальность операций** — операция располагается непосредственно в узле, к которому применяется.
4. **Детерминированность** — одинаковые входные состояния должны приводить к одинаковому результату.
5. **JSON-совместимость** — сообщения должны передаваться стандартными JSON-инструментами.
6. **Полная замена как резервный механизм** — `$set` позволяет заменить любую поддерживаемую структуру целиком.
7. **Независимость от транспорта** — протокол не привязан к конкретному каналу передачи данных.
8. **Минимальная сложность** — новые операции добавляются только при наличии обоснованной необходимости.
