# Layout И Отображение

Этот раздел посвящен логике размещения компонентов: как в matreshka строится layout, когда использовать `stack`, когда `grid`, и зачем нужны алиасы вроде `row`, `column` и `surface`.

## Базовая идея layout

В matreshka layout дерева компонентов в первую очередь строится через контейнеры. Если говорить практично, основной способ собрать свою "flex-раскладку" — использовать `stack`.

Именно `stack` — главный layout-компонент для одномерного размещения:

- по вертикали;
- по горизонтали;
- с gap;
- с выравниванием;
- с padding;
- с scroll;
- с overlays.

При этом сами `overlays` лучше рассматривать как отдельную общую концепцию matreshka, а не только как часть `stack`. Подробно они описаны в [`overlays.md`](overlays.md).

Если нужен свой управляемый flex-layout, почти всегда начинать стоит со `stack`.

Если компоненты нужно поставить в произвольные точки на плоскости и двигать/масштабировать вид, используйте `board`. Это не flex и не `grid`: у каждой карточки свои координаты `x`/`y`, а `center` и `zoom` описывают камеру так же, как у `map`. Подробности — в [components-list.md](../reference/components-list.md).

## Start / End вместо left / right

В документации и API для направлений намеренно используются понятия `start` и `end`, а не `left` и `right`.

Причина в поддержке не только LTR, но и RTL-интерфейсов. В LTR `start` обычно находится слева, а `end` справа. В RTL наоборот: `start` находится справа, а `end` слева.

Направление интерфейса обычно связано с языком пользователя. Например, русский и английский интерфейсы читаются слева направо, поэтому для них используется LTR. Арабский интерфейс читается справа налево, поэтому для пользователя с арабским языком (`language: "ar"` в `client-state`) клиент может использовать RTL-направление.

Практический пример: если кнопку действия нужно поставить в конец строки, не нужно писать "справа". Нужно использовать `end`. Тогда:

- для русского или английского пользователя `end` окажется справа;
- для арабского пользователя `end` окажется слева.

Поэтому, когда нужно описать начало или конец горизонтальной оси, используйте `start` / `end`. Это позволяет одному и тому же BFF-коду корректно работать для разных направлений письма.

## Safe area

Safe area включается явно для `stack` и его алиасов `row`, `column`, `surface`
и `button` через массив `safeArea`. Доступны стороны `SafeAreaSide.Top`,
`SafeAreaSide.Bottom`, `SafeAreaSide.Start` и `SafeAreaSide.End`.

```ts
stack(
  {
    padding: {
      top: 16,
      bottom: 16,
      start: 12,
      end: 12,
    },
    safeArea: [
      SafeAreaSide.Top,
      SafeAreaSide.Bottom,
      SafeAreaSide.Start,
      SafeAreaSide.End,
    ],
  },
  [text("Контент")],
);
```

BFF определяет только стороны, которые нужно защитить. Фактические значения
safe area определяет клиент в зависимости от браузера и платформы. Для каждой
отмеченной стороны итоговый отступ вычисляется как `padding + safe area`.
Поэтому safe area применяется и при нулевом или отсутствующем `padding`.

`Start` и `End` являются логическими сторонами: в LTR они соответствуют левой
и правой сторонам, а в RTL — правой и левой. Передавать `Left` или `Right`
не нужно.

Safe area не определяется автоматически по положению элемента в DOM. Каждый
контейнер с заполненным `safeArea`, включая вложенный, применяет указанные
отступы независимо. Это позволяет BFF явно управлять полноэкранными страницами,
контентом диалогов и стеками внутри overlays.

### `flexItem`, `padding` и `safeArea`

Пиксельный `flexItem.basis` задаёт размер контейнера целиком, вместе с `padding`. Safe
area прибавляется к padding на той же стороне, поэтому контентная область
становится меньше:

```
контент = basis − padding по оси − safe area по оси
```

Это проявляется только при фиксированном `basis`. Если `flexItem: { basis: 56 }` и вертикальный
`padding: 16`, под контент остаётся `24`. Когда на том же контейнере ещё
стоит `safeArea: [Bottom]`, системный inset дополнительно сжимает контент.
Величина inset известна только клиенту и зависит от платформы, поэтому
заложить её в `basis` на BFF нельзя.

При `{ grow: 1 }` контейнер занимает долю свободного места. Padding и safe area
остаются внутри этой доли и не отнимают фиксированный пиксельный бюджет.

`flexItem` считается по оси родителя: в колонке это высота и конфликт дают
`Top` / `Bottom`, в `row` — ширина и конфликт дают `Start` / `End`.

Не совмещайте пиксельный `flexItem` с `safeArea` на одном контейнере. Вынесите
safe area на отдельную обёртку — алиас `stack` (`column`, `row`, `surface`)
без `flexItem` и без `padding`:

```ts
column(
  {
    safeArea: [SafeAreaSide.Bottom],
  },
  [
    surface(
      {
        direction: StackDirection.Horizontal,
        flexItem: { basis: 56 },
        padding: { horizontal: 16 },
      },
      [text("Нижняя панель")],
    ),
  ],
);
```

Внешний контейнер вырастает на системный inset, внутренний сохраняет
авторский `flexItem`. Padding, если он нужен, тоже оставляйте на внутреннем
контейнере, а не на обёртке с `safeArea`.

## `stack` как основной layout-компонент

`stack` — это базовый контейнер для размещения вложенных компонентов.

Пример:

```ts
stack(
  {
    direction: StackDirection.Horizontal,
    gap: 12,
  },
  [text("Первый"), text("Второй")],
);
```

Здесь:

- `direction` задает ось layout;
- `gap` — расстояние между дочерними элементами.

## Что можно настраивать в `stack`

У `stack` много настроек. Самые частые:

- `direction` — вертикаль или горизонталь;
- `align.main` — выравнивание по главной оси;
- `align.cross` — выравнивание по поперечной оси;
- `gap` — промежуток между элементами;
- `padding` — внутренние отступы;
- `safeArea` — стороны, на которых к padding добавляется системный отступ;
- `flexItem` — поведение компонента как flex-item внутри родительского `stack`;
- `overflow` — поведение при переполнении (`auto`, `hidden`, `scroll` и др.);
- `wrap` — перенос элементов на новые строки (`nowrap`, `wrap`, `wrap-reverse`, `balance` и комбинации с `balance`);
- `surface` — фон поверхности;
- `outline` — внешний контур;
- `radius` — скругление;
- `overlays` — наложения;
- `disabled` — отключенное состояние;
- `onClick`, `onKeyDown`, `onScroll` — взаимодействия контейнера.

Пример с несколькими настройками:

```ts
stack(
  {
    direction: StackDirection.Vertical,
    gap: 16,
    padding: 16,
    overflow: Overflow.Auto,
  },
  [text("Первый блок"), text("Второй блок")],
);
```

## `direction`

`stack` может работать в двух основных режимах:

### Вертикальный

```ts
stack(
  {
    direction: StackDirection.Vertical,
  },
  [text("A"), text("B")],
);
```

### Горизонтальный

```ts
stack(
  {
    direction: StackDirection.Horizontal,
  },
  [text("A"), text("B")],
);
```

## `align`

Выравнивание задается через `align.main` и `align.cross`.

Пример:

```ts
stack(
  {
    direction: StackDirection.Horizontal,
    align: {
      main: StackMainAxisAlign.Center,
      cross: StackCrossAxisAlign.Center,
    },
  },
  [text("По центру"), text("По центру")],
);
```

Это полезно, когда нужно не только разместить элементы по оси, но и контролировать их позиционирование внутри контейнера.

## `flexItem`

`flexItem` управляет размером компонента по направлению родительского `stack`.

Практическое правило:

- `{ grow: 1 }` — относительный вес (`flex-grow`);
- `{ basis: 56 }` — размер; число больше `1` в `basis` трактуется как логические пиксели;
- вместо числа в `basis` можно передать `{ value, unit }` или задать явные `grow` / `shrink`.

```ts
import {
  DimensionalUnit,
  column,
  stack,
  text,
} from "@matreshka/bff/components";

column([
  stack({ flexItem: { basis: 240 } }, [text("Sidebar")]),
  stack({ flexItem: { grow: 1 } }, [text("Контент")]),
]);

stack(
  {
    flexItem: {
      basis: { value: 50, unit: DimensionalUnit.Percent },
    },
  },
  [text("Половина родителя")],
);
```

Число в `basis` больше `1` на BFF становится `{ value, unit: px }`. Явный `{ value, unit }` нужен, когда размер задаётся не в пикселях: доступны `px`, `%`, `rem`, `em`, `vw`, `vh`, `vmin`, `vmax`. Фиксированный `basis` без `grow` / `shrink` не растёт и не сжимается.

Это удобно для пропорционального layout внутри `stack`.

Важно понимать, что на стороне BFF такие размеры обычно задаются именно в пикселях, но клиент при рендере конвертирует их в `rem`. Это сделано затем, чтобы итоговый UI масштабировался вместе с базовым размером шрифта и настройками доступности, а не был намертво привязан к фиксированным пикселям.

Пиксельный `basis` (`> 1`) включает `padding`. Если на том же контейнере включён
`safeArea`, системный inset ещё сильнее уменьшает область под контент. Как
собрать фиксированную панель у края экрана — в разделе про
`flexItem`, `padding` и `safeArea` выше.

## `overflow` и `onScroll`

`overflow` задаёт поведение при переполнении содержимого. `Overflow.Auto`
делает контейнер прокручиваемым; `Overflow.Hidden` обрезает содержимое и
запрещает сжатие контейнера. Если `overflow` не задан, клиент ведёт себя как
при `auto`.

```ts
stack(
  {
    overflow: Overflow.Auto,
    onScroll: ({ payload }) => {
      console.log(payload.offset);
    },
  },
  [text("Длинный список")],
);
```

Именно поэтому `stack` часто становится основой для лент, списков и бесконечной прокрутки.

## `wrap`

`wrap` задаёт `flex-wrap`: остаются ли дочерние элементы на одной линии
или переносятся на следующие.

```ts
stack(
  {
    direction: StackDirection.Horizontal,
    wrap: FlexWrap.Wrap,
    gap: 8,
  },
  [text("A"), text("B"), text("C")],
);
```

Если `wrap` не задан, браузер использует `nowrap`. `FlexWrap.Balance` сам по
себе означает `wrap` с равномерным распределением по строкам.
`FlexWrap.BalanceWrapReverse` — то же с обратным порядком строк.

## Алиасы для `stack`

Поскольку у `stack` много параметров, не всегда удобно каждый раз писать полную конфигурацию. Для типовых случаев есть готовые алиасы.

### `column`

`column` — это вертикальный `stack`.

```ts
column([text("Первый"), text("Второй")]);
```

То же самое по смыслу, что:

```ts
stack(
  {
    direction: StackDirection.Vertical,
  },
  [text("Первый"), text("Второй")],
);
```

### `row`

`row` — это горизонтальный `stack`.

```ts
row([text("Первый"), text("Второй")]);
```

То же самое по смыслу, что:

```ts
stack(
  {
    direction: StackDirection.Horizontal,
  },
  [text("Первый"), text("Второй")],
);
```

### `surface`

`surface` — это `stack` с включенным фоном поверхности (`surface: true`).

```ts
surface(
  {
    padding: 16,
  },
  [text("Карточка")],
);
```

Это удобно для карточек, блоков, секций и других визуально выделенных контейнеров.

### `button`

`button` — это тоже специализированный вариант `stack`. По смыслу это горизонтальный `stack` с `surface`, выключенной прокруткой и преднастроенным выравниванием содержимого по центру.

```ts
button([text("Сохранить")]);
```

То есть `button` удобнее воспринимать не как полностью отдельную сущность layout, а как готовый stack-паттерн для интерактивного элемента.

## Когда использовать алиасы

Хорошее практическое правило:

- если нужен просто вертикальный контейнер — `column`;
- если нужна строка — `row`;
- если нужен контейнер с surface-фоном — `surface`;
- если нужен интерактивный контейнер-кнопка с типовыми настройками — `button`;
- если нужна более сложная flex-настройка — `stack`.

То есть алиасы полезны, чтобы не повторять одни и те же базовые параметры каждый раз.

### Как создать свой алиас

По смыслу алиас — это просто удобная обертка над `stack` с заранее заданными параметрами.

Например, можно сделать свой алиас для типовой карточки:

```ts
export function card(
  options: Omit<StackInitConfig<any>, "content" | "surface" | "padding"> = {},
  content: StandaloneComponent[],
) {
  return stack(
    {
      surface: true,
      padding: 16,
      gap: 12,
      ...options,
    },
    content,
  );
}
```

Использование:

```ts
card([text("Заголовок"), text("Описание")]);
```

Идея здесь та же, что у встроенных `row`, `column`, `surface`, `button`: если в проекте часто повторяется один и тот же layout-паттерн, его удобно оформить как собственный алиас компонента.

## `grid`

Если `stack` — основной одномерный layout-компонент, то `grid` нужен для двумерной сетки.

Пример:

```ts
grid(
  {
    columns: 2,
    gap: 16,
  },
  [text("A"), text("B"), text("C"), text("D")],
);
```

Хороший практический пример — строка с двумя одинаковыми по ширине кнопками:

```ts
grid(
  {
    columns: [1, 1],
    gap: 12,
  },
  [button([text("Отмена")]), button([text("Сохранить")])],
);
```

Здесь обе кнопки получают одинаковые колонки сетки. Это важное отличие от `stack`/flex-подхода: во flex относительные размеры работают через распределение свободного места по одной оси, а в `grid` вы заранее описываете сами колонки. Поэтому для сценариев "сделать ровно две одинаковые колонки" или "задать явную структуру таблицы" `grid` часто оказывается понятнее и стабильнее.

`grid` особенно полезен, когда нужны:

- карточки в несколько колонок;
- таблицеподобный layout;
- независимое управление строками и колонками.

### Основные настройки `grid`

У `grid` есть несколько ключевых настроек:

- `columns` — описание колонок;
- `gap` — расстояние между ячейками;
- `surface` — фон контейнера;
- `flexItem` — размер/вес самого `grid` как компонента внутри родительского `stack`;
- `gridItem` у дочерних компонентов — управление размещением конкретной ячейки.

Самая важная из них — `columns`.

### `columns`

`columns` можно задавать несколькими способами.

#### Число

```ts
grid(
  {
    columns: 2,
  },
  [text("A"), text("B")],
);
```

Подходит для простых случаев, когда нужна равномерная сетка по фиксированному числу колонок.

#### Массив размеров колонок

```ts
grid(
  {
    columns: [1, 1, 1],
  },
  [text("A"), text("B"), text("C")],
);
```

Это самый полезный режим для явной структуры колонок.

Можно комбинировать разные типы значений:

- числа;
- `GridColumnSize.Auto`;
- `GridColumnSize.MinContent`;
- `GridColumnSize.MaxContent`;
- объекты `{ min, max }`.

Пример:

```ts
grid(
  {
    columns: [GridColumnSize.MinContent, 1, 1, 1],
    gap: 8,
  },
  [text("ID"), text("Имя"), text("Телефон"), text("Сайт")],
);
```

Это уже очень похоже на обычную таблицу: первая колонка сжимается по содержимому, остальные занимают оставшееся место равномерно.

#### Диапазон `{ min, max }`

```ts
grid(
  {
    columns: [{ min: 160, max: 320 }, 1],
  },
  [text("Первая колонка"), text("Вторая колонка")],
);
```

Такой вариант полезен, когда колонка должна иметь контролируемый диапазон ширины.

#### `subgrid`

```ts
grid(
  {
    columns: GridTemplateColumns.Subgrid,
  },
  nestedContent,
);
```

`subgrid` нужен для вложенных grid-сценариев, когда дочерняя сетка должна наследовать колонки родительской.

### `gap`

`gap` можно задавать:

- одним числом;
- объектом `{ row?, column? }`.

Примеры:

```ts
gap: 16;
```

```ts
gap: { row: 8, column: 16 }
```

Это удобно, когда вертикальные и горизонтальные промежутки должны отличаться.

## `gridItem`

Когда компонент находится внутри `grid`, ему можно задавать `gridItem`.

Идея здесь такая:

- `grid` управляет сеткой в целом;
- `gridItem` управляет размещением конкретного элемента внутри сетки.

Если нужен специфический layout именно внутри сетки, это лучше делать через `gridItem`, а не пытаться решить задачу только через `stack`.

Пример:

```ts
text(
  {
    gridItem: {
      columnStart: 1,
      columnEnd: { span: 2 },
    },
  },
  "Занимает две колонки",
);
```

Через `gridItem` можно управлять:

- `columnStart`
- `columnEnd`
- `rowStart`
- `rowEnd`

Это позволяет делать:

- ячейки на несколько колонок;
- ячейки на несколько строк;
- сложные сеточные блоки внутри одной grid-структуры.

## Как сделать аналог таблицы

`grid` хорошо подходит для табличного отображения данных.

Простой вариант:

```ts
grid(
  {
    columns: [GridColumnSize.MinContent, 1, 1, 1],
    gap: 8,
  },
  [
    column([text("ID")]),
    column([text("Имя")]),
    column([text("Телефон")]),
    column([text("Сайт")]),
  ],
);
```

## Как сделать строку таблицы с `onClick`

Если нужен не просто набор ячеек, а кликабельная строка целиком, удобный паттерн такой:

1. сделать строку отдельным контейнером;
2. заставить ее занять все колонки через `gridItem`;
3. внутри строки построить вложенный `grid`, при необходимости через `subgrid`.

Пример:

```ts
grid(
  {
    columns: [GridColumnSize.MinContent, 1, 1],
    gap: 8,
  },
  [
    text("ID"),
    text("Имя"),
    text("Статус"),
    stack(
      {
        onClick: () => openUser(),
        gridItem: {
          columnStart: 1,
          columnEnd: { span: 3 },
        },
      },
      [
        grid(
          {
            columns: GridTemplateColumns.Subgrid,
          },
          [text("42"), text("Alice"), text("Active")],
        ),
      ],
    ),
  ],
);
```

Идея в том, что клик навешивается не на отдельную ячейку, а на контейнер строки. Это позволяет приблизить поведение к обычной таблице, где строка воспринимается как единый интерактивный объект.

## Что использовать на практике

Самое полезное короткое правило:

### Используйте `stack`, когда

- layout одномерный;
- нужно построить свой flex-контейнер;
- важны `gap`, `align`, `padding`, `scroll`.

### Используйте `row` / `column` / `surface`, когда

- нужен частый типовой вариант `stack`;
- хочется писать короче и понятнее.

### Используйте `grid`, когда

- layout по-настоящему двумерный;
- важны колонки и размещение по сетке;
- `stack` уже начинает быть неудобным.
